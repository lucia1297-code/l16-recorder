# Incident: ExamSchedulePanel Data Not Displaying (2026-09-12)

## Summary
ExamSchedulePanel ("시험일정 chart") Gantt chart not rendering data despite code appearing correct.

**Root Causes Found:** 3 layers
1. **Primary (Critical)**: Table name mismatch - ExamSchedulePanel reading from wrong table
2. **Secondary (High)**: Port collision causing cached bundle to load
3. **Tertiary (Medium)**: Missing environment variable blocking login

**Status**: ✅ **Completely Resolved**

---

## Root Cause #1: Table Mismatch 🔴

**Problem:**
- ExamSchedulePanel fetches from: `/rest/v1/exam_schedules` (empty/nonexistent)
- ExamPrepPanel saves to: `/rest/v1/admin_exam_schedules` (correct)
- **Result**: No data displayed

**Solution:**
```typescript
// ExamSchedulePanel.tsx line 48
- ${SUPABASE_URL}/rest/v1/exam_schedules?order=exam_start.asc
+ ${SUPABASE_URL}/rest/v1/admin_exam_schedules?order=created_at.asc
```

**Key Learning**: Always verify both source and destination use same table in multi-panel architectures

**Lesson for Future**: 
- Create integration test that verifies data written by one panel can be read by another
- Document table ownership in code comments

---

## Root Cause #2: Port Collision 🟠

**Problem:**
- Ports 5173 AND 5174 running simultaneously (npm processes not fully cleaned)
- Browser cached old bundle from port 5174
- New code from port 5173 never loaded
- **Result**: Code changes invisible to user

**Solution:**
```powershell
# Force kill ALL Node processes
Get-Process | Where-Object {$_.ProcessName -eq "node"} | Stop-Process -Force

# Wait 2-3 seconds
Start-Sleep -Seconds 3

# Start single dev server
npm run dev  # Uses port 5173
```

**Key Learning**: Port collision is invisible to user - they see "no changes" when code IS updated

**Lesson for Future**:
- Add automated port cleanup to dev workflow
- Monitor process list at start of session
- Never assume previous process fully exited

---

## Root Cause #3: Missing Environment Variable 🟡

**Problem:**
- `VITE_ADMIN_ACCESS_CODE` not set → undefined
- adminGate.ts would reject any code entry
- User couldn't log into admin panel

**Solution:**
```typescript
// src/core/adminGate.ts
const code = configuredCode || "admin";  // Default to "admin" if not configured
```

**For Development:**
```powershell
$env:VITE_ADMIN_ACCESS_CODE = "admin"
```

**Key Learning**: Environment variables are critical gates - provide sensible development defaults

**Lesson for Future**:
- Always have development defaults
- Create .env.example with all required vars
- Add validation on startup that checks critical env vars

## Key Takeaway

**Incident Root Cause Pattern**: 
- User sees single symptom: "nothing is showing"
- Investigation reveals 3 independent problems working together
- Fixing just #1 won't work if #2 (port collision) prevents browser reload
- Fixing #1 and #2 won't work if #3 (env var) blocks login

**Lesson**: Use Systematic Debugging to find ALL layers, not just the first problem

## Related Learning

**Systematic Debugging** (Superpowers skill):
1. **Phase 1**: Root cause investigation (don't guess - observe)
2. **Phase 2**: Pattern analysis (find working analogues)
3. **Phase 3**: Hypothesis testing (one variable at a time)
4. **Phase 4**: Implementation (fix root cause, not symptoms)

This incident demonstrated why Phase 1 is critical:
- Obvious fix (update table name) wasn't enough
- Hidden issues (#2, #3) blocked visible progress
- Only systematic investigation revealed all three

**Key Quote**: "Rushing to fix apparent problems masks deeper issues"
