# L16 Student Recorder Lite (MVP)

학생들이 휴대폰에서 시험 결과와 오답 데이터를 입력·저장하는 모바일 우선 PWA.
React + TypeScript + Vite + vite-plugin-pwa.

## 가장 쉬운 실행 방법 — 한 번 클릭 (Windows)

이 폴더 안의 **`START.bat`** 파일을 더블클릭하세요. 그게 전부입니다.

- 처음 실행할 때만 자동으로 필요한 파일을 설치합니다 (1~2분)
- 관리자 접속 코드·비밀번호가 없으면 자동으로 만들어서 화면에 보여줍니다
- 잠시 후 브라우저가 자동으로 열립니다
- **이 검은 창(터미널)을 닫으면 서버가 꺼집니다** — 사용하는 동안은 그대로 열어두세요

**지금 자동 생성된 관리자 정보** (처음 실행 시 이 값으로 `.env`가 만들어집니다):
- 관리자 접속 코드: `PVPHPJ` (앱 제목을 5번 연속 탭하면 입력창이 뜹니다)
- 관리자 비밀번호: `OuQBQoczGX`

⚠️ 이 값들은 제가 임의로 생성해서 코드에 넣어둔 것입니다. **보안을 위해 처음 실행 후 `.env` 파일을 열어 직접 원하는 값으로 바꾸시길 권합니다.** (메모장으로 `.env` 파일 열어서 `VITE_ADMIN_ACCESS_CODE=`와 `VITE_ADMIN_PASSWORD=` 뒤 값만 바꾸고 저장 → `START.bat` 다시 실행)

## 핸드폰으로 접속하기 (같은 와이파이 안에서)

1. PC와 핸드폰을 **같은 와이파이**에 연결하세요.
2. `START.bat`을 실행하면 검은 창에 이런 줄이 보입니다:
   ```
   ➜  Local:   http://localhost:5173/
   ➜  Network: http://192.168.0.XX:5173/
   ```
3. **`Network:` 뒤에 나온 주소**(예: `http://192.168.0.XX:5173/`)를 핸드폰 브라우저 주소창에 그대로 입력하세요.
4. 핸드폰 브라우저 메뉴에서 "홈 화면에 추가"를 누르면 앱처럼 아이콘이 생깁니다.

이 방법은 **PC가 켜져 있고 같은 와이파이에 있을 때만** 작동합니다. PC를 끄거나 다른 장소(예: 학원 밖)에서 접속하려면 아래 "진짜 배포" 절차가 필요합니다.

## 어디서나 접속되는 진짜 공개 URL 만들기 (5분, 계정 필요)

이건 제가 여기서 대신 눌러드릴 수 없는 부분입니다(로그인 필요) — 하지만 절차가 아주 간단합니다:

1. `START.bat`이 열려있는 채로 새 터미널(또는 같은 창에서 Ctrl+C 후) 아래 명령 실행:
   ```powershell
   npm run build
   ```
   → `dist` 폴더가 생성됩니다.
2. 브라우저에서 https://app.netlify.com/drop 접속 (가입 없이도 바로 가능, 단 나중에 계속 쓰려면 무료 가입 권장)
3. 방금 만들어진 `dist` 폴더를 그 페이지에 **드래그 앤 드롭**
4. 몇 초 후 `https://random-이름.netlify.app` 같은 진짜 URL이 생깁니다 — 이제 어디서나, 어떤 기기에서나 이 하나의 URL로 접속됩니다.

(Supabase를 아직 안 붙였다면 이 상태로는 데이터가 각 기기의 브라우저에만 저장되니, 여러 학생이 같은 데이터를 보려면 이 시점에 Supabase 연동을 권장합니다 — 아래 "Supabase 로 전환" 참고.)

## 관리자 화면 접속 방법 (학생에게 숨김)

이전에는 화면 상단에 "관리자 →" 버튼이 항상 보였습니다. 이제는 **학생 화면에 관리자로 가는 버튼 자체가 없습니다.**

**접속 방법**: 앱 제목("ASX Student Recorder Lite")을 **2초 안에 5번 연속 탭**하면 접속 코드 입력창이 뜹니다. `.env`의 `VITE_ADMIN_ACCESS_CODE`와 일치하는 코드를 입력하면 관리자 화면으로 진입합니다.

- 이 코드는 로그인 비밀번호(`VITE_ADMIN_PASSWORD`)와는 **다른, 별도의 층**입니다 — 학생이 관리자 로그인 화면 자체를 우연히 발견하지 못하게 막는 용도이고, 통과한 뒤에도 비밀번호(또는 Supabase 로그인)를 또 입력해야 합니다.
- `VITE_ADMIN_ACCESS_CODE`를 설정하지 않으면 **아무도(관리자 포함) 들어갈 수 없습니다** — 기본 통과값이 없습니다. 반드시 `.env`에 설정하세요.
- 한 번 통과하면 그 브라우저 세션 동안은 다시 코드를 안 물어봅니다. 브라우저를 완전히 껐다 켜면 다시 물어봅니다.
- ⚠️ 이 방식만으로는 완벽한 보안이 아닙니다 (코드가 클라이언트 JS 번들에 포함되어 개발자도구로 찾아낼 여지가 있음). "학생이 실수로 못 들어가게" 막는 용도이고, 실질적 보안 경계는 그 다음 단계인 Supabase Auth 로그인입니다.

## 등록 승인 절차 직접 테스트하는 방법

Supabase 없이 localStorage 모드로도 오늘 바로 전체 흐름을 테스트할 수 있습니다.

1. `npm run dev` 로 앱 실행
2. **학생 역할로 등록 신청 만들기**: 전화인증 화면에서 아무 번호 입력 → "인증번호 받기" → Aligo 키 미설정 시 **브라우저 콘솔(F12)** 에 6자리 코드가 찍힘 → 입력해서 인증 → (명부에 이미 다른 학생이 등록돼 있고 이 번호는 없다면) "등록 신청하기" 화면에서 이름·학교·학년 입력 후 신청 → "⏳ 승인 대기 중" 확인
3. **관리자로 전환**: 제목 5번 탭 → 접속 코드 입력 → 로그인 → "등록 신청" 탭에서 방금 신청 확인 → "승인" 클릭 (콘솔에 학생코드 안내 문자 로그 출력)
4. **학생 화면으로 복귀**: "← 학생" 버튼 → 아까 그 화면에서 "승인 확인하기" 클릭 → 학생코드·이름·학교·학년 자동 완성 확인

## 관리자 인증

두 가지 모드가 자동으로 전환됩니다 (`.env` 에 Supabase 키가 있는지로 판단):

**Simple 모드 (기본, 설정 불필요)**
- `.env` 의 `VITE_ADMIN_PASSWORD` 로 로그인 (미설정 시 개발용 기본값 `asx2026` 사용 + 콘솔 경고)
- 이메일 불필요, 비밀번호만 입력

**Supabase 모드 (Supabase 키를 `.env`에 넣으면 자동 전환)**
- Supabase Auth 이메일/비밀번호 로그인으로 자동 전환
- Supabase 대시보드 > Authentication > Users 에서 관리자 계정을 미리 만들어두세요
- 세션은 Supabase가 관리 (로그아웃 버튼 제공)

## 학생을 명부에 등록하는 세 가지 방법

1. **엑셀 일괄 업로드** — 여러 명을 한번에.
2. **관리자 직접 추가** — 명부 관리 탭의 "+ 학생 직접 추가" 버튼. 한 명만 급하게 등록할 때 엑셀 없이 바로 등록. 학생코드는 비워두면 자동 생성됩니다.
3. **학생 자가등록 + 승인** — 학생이 스스로 신청하고 관리자가 승인 (아래 "신규 학생 자가등록 + 관리자 승인" 참고).

세 방법 모두 같은 명부에 쌓이고, 같은 규칙(학생코드 자동생성, 전화번호 형식 검증)을 공유합니다.

## 명부 업로드 (엑셀)

관리자 화면 > "명부 관리" 탭에서 엑셀 파일을 업로드하면 학생코드·이름·학교·학년·전화번호가 한번에 등록됩니다.

**작성 양식**: `student_roster_template.xlsx` (별도 제공) — 열 순서: 학생코드(선택), 이름, 학교, 학년, 휴대폰번호, 담당교사, 비고

**학생코드 자동 생성**: "학생코드" 열을 비워두면 자동 생성됩니다. **무작위 8자리 영숫자 조합**(예: `K5P8Z89W`)으로, 순번이 드러나지 않고 추측이 어렵습니다. 헷갈리기 쉬운 문자(0, 1, I, O, L)는 자동으로 제외해서 학생이 문자로 받아 직접 입력할 때 오타를 줄였습니다. 직접 정한 코드를 쓰고 싶으면 그대로 입력하면 됩니다.

**번호가 바뀐 학생**: 명부 관리 탭의 등록된 명부 표에서 "번호수정" 버튼으로 해당 학생 전화번호만 바로 고칠 수 있습니다 (엑셀 재업로드 불필요). 저장 즉시 예전 번호는 더 이상 인증에 쓸 수 없고, 새 번호로 바로 인증 가능합니다.


**업로드 후 일어나는 일**
- 명부가 한 건이라도 등록되면, 학생 전화인증 단계는 **등록된 번호만 허용**합니다 (등록 안 된 번호는 "선생님에게 문의하세요" 오류).
- 등록된 번호로 인증에 성공하면 학생코드·이름·학교·학년이 **자동으로 채워집니다** (직접 입력 불필요).
- 명부가 비어 있으면(아직 업로드 전) 기존처럼 학생이 직접 모든 정보를 입력합니다 — 하위 호환.
- 관리자는 "명부 관리" 탭에서 학생별로 "전송" 버튼을 눌러 학생코드를 즉시 문자로 보낼 수 있습니다.

**⚠️ xlsx(SheetJS) 라이브러리 버전 주의**
- 이 프로젝트가 사용하는 엑셀 파싱 라이브러리(`xlsx`)는 npm 공개 레지스트리에 등록된 최신 버전(0.18.5)에 알려진 고위험 취약점(프로토타입 오염, ReDoS)이 있습니다. SheetJS는 이후 버전을 npm이 아닌 자체 CDN(`cdn.sheetjs.com`)에만 배포합니다.
- 이 개발 환경은 `cdn.sheetjs.com`에 접속이 차단되어 있어 부득이 npm의 구버전으로 개발했습니다.
- **실제 배포 전에 아래 명령으로 반드시 패치 버전으로 교체하세요** (선생님 PC에서는 정상 접속됩니다):
  ```powershell
  npm uninstall xlsx
  npm install https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz
  ```
  교체 후 `npm run build`로 정상 빌드되는지만 확인하면 코드 수정은 필요 없습니다 (API 호환).



**학생**: 8단계 플로우 맨 앞에 "전화인증" 단계가 추가되었습니다. 휴대폰 번호 입력 → 인증번호 받기 → 6자리 입력 → 인증 완료 후에만 다음 단계로 진행합니다.

**관리자**: 로그인(비밀번호 또는 Supabase Auth) 성공 후, `.env`에 `VITE_ADMIN_PHONE`이 설정돼 있으면 2단계 인증(OTP)이 자동으로 요구됩니다. 미설정 시 2단계 인증은 건너뜁니다.

**SMS 발송 — 알리고(Aligo)**
- `.env`에 `VITE_ALIGO_API_KEY`, `VITE_ALIGO_USER_ID`, `VITE_ALIGO_SENDER`를 모두 채우면 실제 문자가 발송됩니다.
- 하나라도 비어있으면 실제 발송 대신 **브라우저 콘솔에 인증번호가 출력**됩니다 (데모/오늘 바로 테스트 가능).
- 발급: https://smartsms.aligo.in (일반 학원에서 널리 쓰는 국내 SMS API)

**⚠️ 보안 주의사항 (지금 구현의 한계, 정직하게 안내)**
- 현재 구현은 **클라이언트(브라우저)에서 직접** Aligo API를 호출합니다. 즉 `.env`에 넣은 API 키가 브라우저 네트워크 요청에 노출됩니다. 빠른 테스트/데모에는 문제없지만, **실제 학생들에게 배포하기 전에는 반드시 서버 뒤로 옮기세요.**
- 인증번호 세션도 현재는 **localStorage**에 저장됩니다 (개발자도구로 열람 가능). 운영 수준 보안이 아닙니다.
- 운영 전환용 템플릿을 `supabase/functions/send-otp/index.ts`, `supabase/functions/verify-otp/index.ts`에 제공했습니다. 이 두 Edge Function을 배포하면 API 키와 인증번호가 서버에만 존재하게 됩니다. (배포: `supabase functions deploy send-otp` 등 — 이 환경에서는 Supabase CLI/API에 접속할 수 없어 제가 직접 배포·테스트하지 못했습니다.)
- 이 환경(제가 코드를 작성하는 샌드박스)은 Aligo·Supabase API 서버에 네트워크 접근이 차단되어 있어, **실제 문자 발송이 되는지는 제가 직접 확인하지 못했습니다.** 선생님 PC에서 `.env`를 채우고 `npm run dev`로 직접 테스트해 주세요.

## 과제 관리 (신규)

**관리자**: "과제 관리" 탭에서 과제 유형을 최대 8개까지 자유롭게 만들 수 있습니다 (이름 + 지정 개수, 예: "모의고사 풀이" 5회). 학생별로 유형별 제출 개수를 실시간으로 보여주는 현황표가 함께 제공됩니다.

**판정 기준** (개수 기준):
- 지정 개수만큼 다 제출 → **good**
- 일부만 제출 → **not bad**
- 하나도 제출 안 함 → **경고**

지정 개수를 늘리면(예: 3→6) 기존 제출 건수는 그대로 누적되므로, 자연스럽게 "이월"되어 계속 관찰됩니다 — 주기가 리셋되지 않습니다.

**학생**: 전화인증 후 "과제 제출하기"를 선택 → 과제 유형 선택 → 회차·점수(선택)·틀린 문항 번호(선택, 자유 입력) 입력 → 제출. 모의고사 풀이처럼 1~5회 이상 자유롭게 추가 등록할 수 있습니다.

**제출 시 자동 알림**: 과제가 제출되면 관리자(`VITE_ADMIN_PHONE`)와 학부모(명부에 등록된 학부모번호)에게 자동으로 SMS가 발송됩니다. 발송 실패해도 제출 자체는 저장됩니다.

**학부모 번호 등록**: 엑셀 명부의 "학부모번호(선택)" 열에 입력하거나, 명부 관리 > 학생 직접 추가 시 함께 입력할 수 있습니다.

**알림 방식**: 지금은 SMS(알리고)로 발송합니다. 카카오 알림톡으로 전환하고 싶으면 `SmsProvider` 인터페이스를 구현하는 새 클래스만 추가하면 되도록 설계했습니다 (기존 `AligoSmsProvider`/`ConsoleSmsProvider`와 동일한 패턴).

## 신규 학생 자가등록 + 관리자 승인

명부에 없는 번호로 학생이 전화인증을 완료하면, 무조건 막는 대신 **직접 등록을 신청**할 수 있습니다.

**학생 쪽**
1. 전화번호 인증 완료 (명부에 없는 번호도 인증 자체는 가능 — 본인 확인 목적)
2. 명부에 없으면 이름·학교·학년 입력 후 "등록 신청하기"
3. "⏳ 승인 대기 중" 화면 표시. "승인 확인하기" 버튼으로 언제든 재확인 가능 (승인 전까지 다음 단계로 진행 불가)

**관리자 쪽**
- "등록 신청" 탭에 대기 건수가 실시간으로 표시됩니다.
- **승인**: 학생코드가 자동 생성(`S1001` 형식)되어 명부에 등록되고, 즉시 그 학생 번호로 코드가 문자 발송됩니다 (발송 실패해도 승인 자체는 유지).
- **거부**: 신청을 삭제합니다. 학생은 이후 재신청 가능합니다.
- 승인은 관리자가 확인할 때까지 시간이 걸릴 수 있습니다 — 학생 화면은 그 사이 재확인 버튼을 안내합니다.

## Supabase 로 전환 (선택)

1. Supabase 프로젝트 생성 후 `supabase/schema.sql` 을 SQL Editor 에서 실행
   - RLS 정책: 학생 제출(insert)은 익명 허용, 조회(select)는 로그인한 관리자만 허용
2. Authentication > Users 에서 관리자 계정(이메일/비밀번호) 생성
3. `.env` 파일 생성 (`.env.example` 참고):
   ```
   VITE_SUPABASE_URL=...
   VITE_SUPABASE_ANON_KEY=...
   ```
4. 끝 — `npm run dev` 재시작하면 자동으로 Supabase 저장 + Supabase 로그인으로 전환됩니다.
   (코드 수정 불필요: `storageFactory.ts`/`authFactory.ts` 가 환경변수를 감지해서 자동 전환)

> 참고: `@supabase/supabase-js` 는 이미 `package.json` 에 포함되어 `npm install` 시 함께 설치됩니다.
> 이 환경에서는 Supabase API에 직접 접속해 실제 연동 테스트를 하지 못했습니다 — 선생님 PC에서 위 절차대로 `.env`를 채우고 `npm run dev` 후 직접 확인해 주세요.
