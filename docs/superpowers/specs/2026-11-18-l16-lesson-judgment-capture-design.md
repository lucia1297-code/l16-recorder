# L16 수업 기록·교수 판단 진화 설계

## 목적

L16의 기존 학생별 수업 기록 흐름에 문항별 초간편 결과와 강사 판단 변화를 연결한다. 수업 중에는 정답·오답·보류·미확인 또는 J-01~J-04를 한 번 눌러 기록하고, 근거와 해석은 수업 뒤 선택적으로 보완한다.

## 확인된 현재 구조

- `LessonOverviewPanel`은 학생·수업일을 선택하고 오늘 수업, 다음 수업, 교사 메모, 후속 처리, 기존 메모장 연결을 제공한다.
- `teacher_logs`와 `TeacherLog`는 학생·날짜당 한 행을 upsert한다. 수정 이력을 보존하는 이벤트 저장소가 아니다.
- `item_bank`, `item_responses`, `item_sessions`가 문항, 학생 답안, 시험 회차를 보유한다. `item_responses`는 문항·학생·회차별 답을 저장하며 강사의 관찰·해석과 목적이 다르다.
- `teacher_logs`는 authenticated 정책이고 문항 관련 표는 anon 정책도 갖는다. 강사 판단 기록은 문항 응답 표에 넣지 않는다.
- `LessonOverviewPanel`의 수업 기록과 메모는 서로 다른 저장소에 저장된다. 새 이벤트는 기존 로그와 메모를 대체하지 않는다.

## 결정된 접근

기존 수업 화면에 빠른 기록 UI를 추가하고, 판단 이벤트 및 상세 보완 이력을 별도 저장소에 둔다. 선택된 학생·수업일·문항은 화면 상태에서 가져오며, 선택 정보가 없을 때도 이벤트를 미연결 상태로 저장해 나중에 연결한다.

### 원터치 이벤트

- 문항 결과: `correct`, `incorrect`, `hold`, `unverified`.
- 선택형 원인: `vocabulary`, `sentence_structure`, `logic`, `inference`, `choice_judgment`, `time`, `other`.
- 강사 판단 코드: `J-01` 판단 변경, `J-02` 새로운 발견, `J-03` 설명 효과, `J-04` 사후 검토.
- 이벤트는 클라이언트 UUID, schema version, recorded time, 작성자, 선택적 student/session/item 참조, 필수 lesson date, 종류, 상태, payload를 가진다. lesson date는 session link가 비어도 저장한다. 개인 이름은 이벤트에 복제하지 않는다.
- `hold`는 강사가 판단을 의도적으로 보류한 상태이고, `unverified`는 정오·근거가 아직 확인되지 않은 상태다. 이 둘은 구분해 필터링한다.
- 더블 탭과 재전송은 동일 event UUID로 멱등 처리한다. 저장 실패는 사용자에게 표시하고 재시도할 수 있게 한다.

### 사후 보완 및 변경 이력

원터치 이벤트는 수정 덮어쓰기하지 않는다. 후속 보완은 별도 revision 행에 추가한다. 다음 필드를 서로 구분한다: 계획/최초 가설, 관찰된 사실, 학생 진술, 강사 해석, 판단 변경 이유, 적용 전략, 교정 후 관찰 결과, 다음 검증 가설. 비어 있는 상세 보완도 유효한 이벤트다.

### 수업 전·중·후 흐름

- 수업 전: `lesson_plan_saved` 이벤트에 예상 취약 영역, 확인 문항, 최초 설명 전략을 기록한다.
- 수업 중: 문항 결과 또는 J-01~J-04 이벤트를 누른다.
- 수업 후: 필요한 이벤트만 선택해 상세 revision을 저장한다. 계획과 실제는 이벤트 시간순으로 비교하며 기존 teacher log는 변경하지 않는다.
- 동일 문항 전략 변화는 `item_id`와 선택적 version을 기준으로 시간순 조회한다.

### 저장 및 권한

- 논리 테이블은 `lesson_judgment_events`와 append-only `lesson_judgment_revisions`다. 새 SQL migration은 코드 산출물로만 준비하며 승인 없이 운영 DB에 실행하지 않는다.
- 두 표 모두 RLS를 켜고 `authenticated` 사용자만 본인 `created_by = auth.uid()` 기록을 읽거나 추가할 수 있게 한다. revision에는 update/delete 정책을 주지 않는다.
- 온라인에서 Supabase 저장을 쓰더라도 먼저 브라우저 outbox에 event UUID와 최소 연결값을 보관한다. 서버 저장 성공 뒤 큐에서 제거한다. 사용자 이름과 연락처는 outbox에 복제하지 않는다.
- 미연결/미동기화 상태와 가장 오래된 대기 기록 나이를 화면에 보인다. 큐는 자동 만료하지 않고, 명시적 사용자 삭제 또는 동기화 성공 시에만 제거한다. 수동 삭제 전 경고한다. 실제 학생 기록 사용 전에는 운영 보존 기간을 별도 확정한다.

## 화면 구성

기존 `LessonOverviewPanel`의 학생·수업일 및 기록 편집부 안에 다음을 배치한다.

1. 선택 학생·수업일과 선택적 문항 ID 입력. 문제은행에서 정답 포함 문항 데이터를 가져오지 않는다.
2. 문항 결과 버튼 4개와 선택형 중요 오답 원인.
3. J-01~J-04 버튼. 누르면 즉시 저장 상태와 시간 표시.
4. 현재 수업의 최근 기록 목록: 미연결, 상세 보완 필요, 동기화 대기 표시.
5. 수업 후 보완 편집부: 사실·학생 진술·강사 해석·미검증 가설을 분리.
6. 이력 보기: 계획→관찰→판단 변경→교정 결과를 날짜·문항 기준으로 표시.

모바일에서는 버튼을 터치하기 쉽게 세로 배치하고, 수업 중 모달·필수 자유 입력·키보드 입력을 요구하지 않는다.

## 비목표와 제한

- 자동 학생 진단, 추천, 문항 생성, 성적 순위 및 AQOS/APOS/HELIX 분석은 구현하지 않는다.
- 확인되지 않은 ASX·GUIDE-ONE·Teacher Recorder API가 있다고 가정하지 않는다. 데이터 계약 문서까지만 작성한다.
- 실제 학생 기록 입력, 운영 DB migration 적용, GitHub Pages 배포, 운영 브라우저 세션을 사용한 변경은 이번 범위에서 제외한다.
- 실제 90분 수업의 기록 시간·누락률은 실사용 데이터가 없으면 검증 완료로 주장하지 않는다.

## 완료 기준

- 정상·실패·오프라인·재시도·중복 터치에서 이벤트가 유실되거나 중복 생성되지 않는다.
- 미연결 기록을 나중에 학생·수업·문항에 붙일 수 있다.
- 기존 수업 기록, 메모 연결, 문항 응답 기능에 변경이 없다.
- 변경 이력은 append-only로 남고, 사실·진술·해석·가설이 섞이지 않는다.
- 기술 테스트와 빌드가 통과한다. UI의 입력 목표(일반 5초, 중요 15초)는 로컬 상호작용 테스트와 추후 실제 수업 측정을 구분한다.
