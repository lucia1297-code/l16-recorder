# L16 녹음 재분석 오류 조사 및 수정

## 현재 상태

코드 수정과 로컬 검증 완료. 운영 배포 및 실제 학생 녹음의 전사 성공은 미완료.
운영 OpenAI 인증 검사는 HTTP 401 / invalid_api_key를 반환한다. 유효한 자격 증명이 필요하다.
키 값, 서명 URL, 학생 녹음 내용은 이 문서 및 진단 출력에 포함하지 않는다.

## 확인한 사실

- 현재 사용자 화면 주소: https://lucia1297-code.github.io/l16-recorder/
- 조사 기준 소스: 53cb964a906a47b9aed7c0caff699f2085ce193c
- 해당 소스의 GitHub Actions 빌드는 성공했으며 dist는 Git 추적에서 제거되어 있다.
- 실제 서비스의 RecordingPanel-CXDJbogt.js에 OpenAI 키가 존재하지만, 해당 키를 OpenAI의 whisper-1 모델 조회에 사용하면 HTTP 401, error.code=invalid_api_key가 반환된다. 키 미주입만으로 설명할 수 없다.
- 화면의 38:56 녹음: 37,644,424 bytes. Whisper 요청 한도인 25 MiB를 초과한다.
- 화면의 69:33 녹음: 5,860,099 bytes. 파일 크기 한도 이내이다.
- 두 녹음 모두 Supabase 서명 URL 생성 및 원본 HEAD 요청 HTTP 200.
- 원래 브라우저의 Failed to fetch는 요청 단계를 기록하지 않아 당시 개별 요청의 실패 원인까지 직접 입증한 것은 아니다. 위 인증 실패와 크기 초과는 실측한 독립적인 장애 조건이다.
- OpenAI 한도 근거: https://help.openai.com/en/articles/7031512-whisper-audio-api-faq

## 변경

- 녹음 전사 코드를 recordingTranscription.ts로 분리.
- 키 누락 및 HTTP 401을 명확하게 표시하고, 큰 파일 전송 전에 인증 확인.
- 모델 조회 권한만 제한된 키의 HTTP 403은 전사 자체를 시도할 수 있도록 허용.
- 24 MiB 이하 녹음은 기존 형식으로 전송. 초과 녹음은 AudioContext의 16 kHz 디코딩 후 모노 PCM WAV로 약 5분씩 변환하여 순차 전사.
- 압축 파일의 바이트를 단순 절단하지 않으며, 마지막 1초 미만 조각은 앞 구간에 병합.
- 인증/전사 요청에 시간 제한을 적용하고, API 응답의 원문에 키가 포함될 가능성이 있어 원문을 오류로 노출하지 않음.
- 재분석 화면에 다운로드/전사/GPT/저장 단계를 표시.
- 컴퓨터와 휴대폰을 번갈아 사용할 수 있도록 최근 3시간 내 같은 학생 녹음의 세션 ID를 오디오 경로에 유지한다. 두 번째 기기에서 녹음을 시작하면 해당 세션을 이어간다는 안내를 표시한다. 동시 녹음 잠금과 통합 세션 서버 API는 운영 배포 전 추가 구현이 필요하다.
- 결과 저장 HTTP 실패 시 완료로 표시하지 않고, 실패해도 버튼의 처리 중 상태를 해제.

## 검증

- 녹음 회귀 테스트 6개 통과. 최초 미구현 상태에서 4개 실패 후 구현하여 통과 확인.
- 실제 브라우저 합성 오디오 검증 통과: 28,800,046 bytes 입력을 9,600,044 / 9,600,044 / 9,600,046 bytes의 WAV 3개로 변환. 14,400,001개 샘플을 모두 보존하고 전사 결과 순서 확인.
- 브라우저 테스트의 OpenAI 응답은 모의 응답이다. 실제 학생 녹음의 Whisper/GPT 성공을 의미하지 않는다.
- 전체 src 테스트: 177개 중 175개 통과, 기존 과제 유형 상한 테스트와 OTP 전화번호 확인 테스트 2개 실패. Node 25의 Web Storage 간섭을 비활성화하고 모의 Supabase 환경변수를 사용했다.
- 전체 타입 검사: 변경하지 않은 src/App.tsx:123의 Window.__updateDismissed 타입 오류 1건.
- 로컬 Vite/PWA 빌드 성공 확인. dist는 배포하거나 Git에 추가하지 않는다.

## 재개 조건 및 검증 순서

1. 유효한 OpenAI 자격 증명 설정이 필요하다. 채팅이나 소스에 키를 넣지 않는다.
2. 현재 VITE 키를 브라우저에 포함하는 구조는 그대로 남아 있다. 키를 서버 측으로 옮기는 구조 변경은 이번 패치에 포함하지 않았다.
3. 최신 수정 소스로 GitHub Actions 빌드 및 배포 후 실제 서비스의 새 RecordingPanel 자산을 확인한다.
4. 열린 앱의 기존 PWA 캐시가 아니라 새 버전인지 확인한다.
5. 두 녹음을 재분석하고 전사, GPT 분석, DB 저장 및 화면 완료 상태까지 확인한다.
6. 이 검증 전에는 해결 완료로 표시하지 않는다.

## 지속할 작업 원칙

dist는 Git에 커밋하지 않는다. 운영 배포는 GitHub Actions에서 생성한 빌드만 사용한다. 빌드 성공과 API 기능 성공을 구분한다.
